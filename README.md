# 宠知微（PetCare）

面向猫狗主人的宠物健康档案与记录工具。使用响应式 Web + PWA 实现，一套代码同时适配手机与电脑浏览器，可添加到桌面使用。

## 主要功能

- 首页：桌面端左侧竖向导航 + 中间内容区，6 张猫狗照片自动轮播；快捷记录身体情况/就医/生活照，单宠物直达、多宠物先选择、无宠物引导建档
- 宠物概览：健康记录、就医记录、生活照等统计可点击进入栏目；最近记录按时间倒序汇总身体情况、就医、疫苗、驱虫、用药与生活照，支持类别和日期范围筛选，点击可回到原记录
- 图片查看：生活照与检查报告支持大图查看并可返回当前记录；检查报告可下载原图
- 账号：用户名 + 密码注册与登录，登录页区分「用户登录 / 管理员登录」；未登录访问详情页，登录后返回原页面
- 宠物档案：昵称、猫/狗、品种、性别、生日、绝育状态、头像、备注，支持多只宠物
- 身体状况：按日期记录体重（含趋势图）、体温、饮食、饮水、排便/排尿、呕吐、精神状态、症状、过敏史
- 用药记录：药名、剂量、频次、起止日期
- 就医记录：就诊日期、医院、医生、科室、主诉、诊断、处方、费用、复诊日期，支持上传多张检查报告图片
- 防疫驱虫：疫苗名称/针次/日期/下次到期；驱虫类型/日期/下次到期
- 到期提醒：列表展示下次到期日，7 天内到期或已逾期高亮，首页提供「即将到期」汇总
- 生活照：图片、文字说明、标签
- 图片上传：头像、生活照、检查报告均支持点击选择和拖拽上传；生活照区分「已保存」与「本次新选择、尚未保存」，失败后保留文件可重试；前后端统一 JPG/PNG/WEBP、单张 5MB 限制
- 日期校验：前后端校验真实日历日期，拒绝 2026-02-31、2026-13-01、非闰年 2-29 等；疫苗、驱虫、复诊等未来计划日期允许
- 账号设置：修改密码、导出全部数据（JSON）、注销账号
- 管理后台：统计概览、用户列表、只读查看用户宠物与全部记录、禁用/启用、重置密码、删除用户
- PWA：支持添加到主屏幕，移动端底部导航与响应式布局

## 技术栈

| 层 | 选型 |
|---|---|
| 前端 | React 18、TypeScript、Vite、React Router、Tailwind CSS、Recharts、vite-plugin-pwa |
| 后端 | Node.js、Express、JWT（httpOnly Cookie）、bcryptjs、multer |
| 数据库 | SQLite（Node.js 内置 `node:sqlite`） |

## 运行环境

- 实际开发与验收环境：**Node.js v24.14.0**、npm 11.9.0（Windows 11）
- 理论最低版本：Node.js **22.5**（项目使用内置 `node:sqlite`）；**22.x 未实测**，仅 24.14.0 验证通过
- 已验证的启动方式：
  - `npm run dev`：Vite 5173 + 后端 3001，`/api` 代理正常
  - `npm run build && npm start`：Express 托管构建产物，3001 访问正常
- 现代浏览器（Chrome / Edge / Safari / Firefox）
- 启动时出现 `SQLite is an experimental feature` 警告属正常现象

## 快速开始

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量（Windows 可用 copy .env.example .env）
cp .env.example .env
```

编辑 `.env`，至少填写：

| 变量 | 说明 |
|---|---|
| PORT | 服务端口，默认 3001 |
| JWT_SECRET | 登录令牌签名密钥，请填写 32 位以上随机字符串 |
| ADMIN_USERNAME | 管理员账号名 |
| ADMIN_PASSWORD | 管理员初始密码（仅首次初始化时使用） |

```bash
# 3. 初始化数据库（建表 + 创建管理员账号）
npm run db:init

# 4a. 开发模式（前端 5173 + 后端 3001，热更新）
npm run dev
# 浏览器访问 http://localhost:5173

# 4b. 生产模式（构建后由 Express 统一托管）
npm run build
npm start
# 浏览器访问 http://localhost:3001
```

管理员账号由初始化脚本根据 `.env` 创建，数据库中只保存 bcrypt 哈希，仓库与文档中不包含明文口令。

## 数据存储与备份

- 数据库文件：`data/petcare.db`
- 上传图片：`uploads/pets/<宠物ID>/`
- 两者均已加入 `.gitignore`。迁移或备份时，同时复制 `data/` 与 `uploads/` 即可。

## 上传限制

- 支持点击选择与拖拽上传
- 仅支持 JPG / PNG / WEBP
- 单张最大 5MB
- 就医报告一次最多 6 张
- 前端与后端使用相同的格式、大小限制和提示文案；前端校验不通过时不会发起请求

## 日期校验

- 后端校验真实日历日期：拒绝不存在的日期（如 2026-02-31、2026-13-01、2026-04-31）和非闰年的 2 月 29 日
- 闰年日期有效（如 2024-02-29）
- 疫苗、驱虫、复诊等未来计划日期允许填写
- 前端表单在提交前执行相同规则的校验

## 注意事项与已知限制

- 依赖 Node.js 22.5+ 的内置 SQLite；实际只在 Node 24.14.0 上验证，22.x 兼容性未实测。
- `npm run dev` 的 5173 端口默认只监听本机，手机访问请使用 `npm run build && npm start` 的 3001 端口。
- 未接入短信或邮件服务，因此不提供找回密码；忘记密码需管理员在后台重置。
- 管理员对用户业务数据为只读，仅可执行账号管理操作（禁用/启用、重置密码、删除）；禁用用户后其已有登录态也会失效。
- 图片通过带登录态的接口访问，未登录直接访问图片地址会返回 401。
- 手机真机访问本地服务需与电脑处于同一局域网，并访问电脑的局域网 IP:3001。
- PWA 安装能力在 `localhost` 或 HTTPS 下生效。
- `node:sqlite` 目前仍标记为实验特性，不影响本项目功能。
- 首页轮播照片来自 [Unsplash](https://unsplash.com/license)，已下载到 `client/public/hero/` 本地使用；如用于正式发布请自行确认授权与署名要求。
- 主 JS 包约 662 kB，构建时提示 chunk 偏大；不影响课程验收，后续可按页面拆包。
